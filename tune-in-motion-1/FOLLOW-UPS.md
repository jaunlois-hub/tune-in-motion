# Tune In Motion — Deferred Work

These items were called out during a code-quality pass but deliberately not attempted in the same change set because they are large refactors that need verification in a browser session. Pick them up as separate, focused PRs.

## 1. Consolidate AudioContext + MediaStream

**What's there now:** Each audio hook (`usePitchDetection`, `useAudioMonitoring`, `useReferenceTone`, `useGuitarEffects`, `useChordDetection`, `useSmartDrummer`, `useVocalRecorder`, `useLoopRecorder`, `useMetronome`, `useDrumMachine`) creates its own `AudioContext` and most call `getUserMedia` independently.

**Why it matters:**
- Browsers cap concurrent `AudioContext`s (~6 on Chromium). Hitting the cap silently fails to start an effect or recorder.
- Asking for the same input device twice can fail on certain audio interfaces (especially exclusive-mode WASAPI on Windows).
- The two recent additions (input-device selection + output sink-id) have to be plumbed through every hook individually. A shared context would centralize that.

**Suggested shape:**
1. Add `src/audio/AudioGraphProvider.tsx` that owns a single `AudioContext` and a single shared input `MediaStream`.
2. Provide `useAudioGraph()` returning `{ ctx, getInputSource(): MediaStreamAudioSourceNode }`. Each consumer asks for a fresh source node from the shared stream rather than re-`getUserMedia`-ing.
3. Apply `setSinkId` once at the provider level when output device changes.
4. Migrate hooks one at a time. Pitch detection / monitor / reference tone first since they're the simplest.

## 2. Split EffectsSection.tsx

`src/components/sections/EffectsSection.tsx` is ~571 lines and contains:
- The pedal-effects engine UI (knobs, power button)
- The Tone Library preset grid (built-in + user presets, with search and genre filter)
- The YouTube Tone Matcher card
- The Drum Machine card
- The save-preset dialog

It still builds and reads cleanly, but each subsection could move to its own component file under `src/components/sections/effects/` for the same reason the Reference Tone player was extracted from `GuitarTuner` — it makes future edits safer. The Tone Library and the pedal engine share `updateSetting` callbacks, so factor that into a small zustand store (mirroring `useTunerPrefs`/`useTuningSelection`) before the split.
